# UC-LEARNING-REVIEW-AND-RECORD — Review and Strengthen Knowledge

## Situation
A Repetition Map item is selected for the initial pass, is due later, or a concrete learning workflow explicitly requests additional formative practice.

The ordinary map may contain different work by Retention Class/band:
- `CORE | WORKING | RECOGNITION` and their active-recall boundary bands → active recall against the authoritative Review Scope at the useful depth for the current context;
- `MAP_ONLY` → lightweight map/relationship refresh;
- `RECOGNITION ↔ MAP_ONLY` → either lightweight recognition/map refresh or active recall when current context justifies it;

## Result
The requested knowledge is revisited at the intended depth, findings are routed correctly, and only real review evidence updates memory state/history.

For active recall:
- recall happens before opening the Unit;
- the answer is checked against the Review Scope;
- memory gaps are separated from knowledge/source gaps;
- actual review/history evidence is recorded when useful; the next date is chosen from real performance/context.

For `MAP_ONLY` refresh:
- the owner refreshes existence, semantic location, purpose, and useful comparisons/links;
- no full 0–4 recall score is required by default.

For locally requested formative practice:
- the owning workflow may use the same Review Scope and review modes;
- it does not create a universal maturity state.

## Process
1. Resolve the Knowledge ID and authoritative Review Scope/map-refresh scope.
2. Determine the event type from the Repetition Map or caller: `CALIBRATION`, `FULL`, `TARGETED`, `QUESTIONS_ONLY`, `MAP_REFRESH`, `SOURCE_REPAIR`, or local formative practice.
3. For recall-bearing events, hide the content before recall.
4. Choose a useful mode when appropriate: `EXPLAIN`, `CONTRAST`, `DIAGNOSE`, `DECIDE`, `TRANSFER`, `RECOGNIZE`.
5. Compare the result with the Review Scope at the depth expected by Retention Class.
6. For active recall, assign the optional 0–4 score only after checking when the scale is useful; any Recall-State interpretation must come only from real evidence, and it does not require a mandatory stored state column.
7. For `MAP_REFRESH`, update only the lightweight map-refresh evidence/date needed by policy.
8. Route knowledge-base gaps/new questions outward to Coverage & Expansion rather than mis-scoring them as forgetting.
9. Append real review history when useful; never fabricate earlier events.
10. Choose the next map date from the current Retention Class, actual review evidence, workload, and current context; policy defaults are guidance rather than mandatory transitions.

## Materialization boundary
The D+2 learning materialization pass is a first learning/review contact and Repetition Map entry point, but it is not this Use Case's blind-recall calibration unless an actual recall-before-reading event separately occurs.

## Ownership boundary
This Use Case does not own Knowledge ontology, priority dimensions, Expansion planning, or the learning-batch lifecycle.
