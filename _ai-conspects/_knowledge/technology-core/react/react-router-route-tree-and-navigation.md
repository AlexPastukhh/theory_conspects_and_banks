# React Router route trees and navigation

Knowledge ID: `react.react-router-route-tree-and-navigation`

Topic: `react`

## Choosing a router style

A route-object data router enables loaders, actions, route-level errors, fetchers and navigation state:

```jsx
import {
  createBrowserRouter,
  RouterProvider,
} from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      { index: true, element: <Home /> },
      {
        path: "users",
        element: <UsersLayout />,
        children: [
          { index: true, element: <UsersHome /> },
          {
            path: ":userId",
            element: <UserProfile />,
          },
        ],
      },
    ],
  },
]);

export default function App() {
  return <RouterProvider router={router} />;
}
```

A simple declarative router is sufficient when route data APIs are not needed:

```jsx
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
  </Routes>
</BrowserRouter>
```

Use a data router when the application relies on:

```text
loader
action
errorElement
Form
useLoaderData
useNavigation
useFetcher
redirect
automatic revalidation
```

## Route trees and `<Outlet />`

Nested route objects form a tree.

```text
parent route
    renders its element
    owns layout/UI shared by descendants

child route
    renders inside the nearest parent <Outlet />
```

Example:

```jsx
function RootLayout() {
  return (
    <>
      <Header />
      <Outlet />
    </>
  );
}
```

Child paths are normally relative:

```jsx
{
  path: "settings",
  element: <Settings />,
}
```

under `/` becomes `/settings`.

An index route has no `path` and renders when its parent URL matches exactly:

```jsx
{
  index: true,
  element: <DashboardHome />,
}
```

## Links and active links

`<Link>` performs client-side navigation without a full document reload:

```jsx
<Link to="/settings">Settings</Link>
```

`<NavLink>` also knows whether the target matches the current URL:

```jsx
<NavLink
  to="/settings"
  className={({ isActive }) =>
    isActive ? "active" : undefined
  }
>
  Settings
</NavLink>
```

Use `NavLink` for navigation UI that needs active or pending styling.

## Programmatic navigation

`useNavigate()` is for component-driven navigation:

```jsx
const navigate = useNavigate();

navigate("/login");
navigate(-1);
```

Useful options include:

```jsx
navigate("/settings", {
  replace: true,
  state: { from: location.pathname },
});
```

Rules of thumb:

```text
inside a component/event/effect -> useNavigate or <Navigate />
inside a loader/action -> return or throw redirect(...)
```

## URL parameters

Route parameters come from dynamic path segments:

```jsx
{
  path: "users/:userId/posts/:postId",
  element: <UserPost />,
}
```

Read them with:

```jsx
const { userId, postId } = useParams();
```

Nested routes inherit parent parameters.

Query-string state is separate:

```jsx
const [searchParams, setSearchParams] =
  useSearchParams();

const page = searchParams.get("page");
setSearchParams({ page: "2" });
```

Use route params for identity/hierarchy and search params for filtering, sorting, pagination or view state.

## `useLocation()`

`useLocation()` returns the current router location:

```jsx
const location = useLocation();
```

Common fields:

```text
location.pathname
location.search
location.hash
location.state
location.key
```

`location.state` is extra navigation state and is not encoded in the URL.

`location.key` identifies a history entry. It is generated by the history/router integration and should normally be treated as opaque.

Use `useLocation()` for:

```text
reacting to navigation changes
reading state passed by Link/navigate
analytics
breadcrumbs or active sections
manual query parsing when useSearchParams is not used
```
