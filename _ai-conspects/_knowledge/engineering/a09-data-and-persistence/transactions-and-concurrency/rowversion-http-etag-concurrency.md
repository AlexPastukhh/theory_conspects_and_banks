# SQL Server rowversion as an HTTP ETag concurrency token

Knowledge ID: `ef-core.rowversion-http-etag-concurrency`

Topic: `ef-core`

SQL Server `rowversion` is generated by the database and changes whenever that row is updated. EF Core does not increment it in application code. Mapping the column as a concurrency token makes it useful both for EF's optimistic-concurrency check and as the source of a strong HTTP ETag.

```csharp
public sealed class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = null!;
    public decimal Price { get; set; }

    [Timestamp]
    public byte[] RowVersion { get; set; } = null!;
}

// Fluent alternative
modelBuilder.Entity<Product>()
    .Property(product => product.RowVersion)
    .IsRowVersion();
```

Encode the database bytes as a quoted Base64 ETag. HTTP entity tags require quoted syntax:

```csharp
static EntityTagHeaderValue ToETag(byte[] rowVersion)
{
    var token = Convert.ToBase64String(rowVersion);
    return new EntityTagHeaderValue($"\"{token}\"");
}
```

## Conditional reads

A GET computes the current ETag, compares all supplied `If-None-Match` values using the comparison rules appropriate to cache validation, and returns either the representation or a bodyless `304`. Wildcard `*`, multiple validators, quoted syntax, and strong-versus-weak comparison must be handled deliberately. The relevant validator is still emitted on `304`.

```csharp
var product = await db.Products
    .AsNoTracking()
    .SingleOrDefaultAsync(item => item.Id == id);

if (product is null)
    return NotFound();

var etag = ToETag(product.RowVersion);

if (IfNoneMatchSatisfied(Request, etag))
{
    Response.GetTypedHeaders().ETag = etag;
    return StatusCode(StatusCodes.Status304NotModified);
}

Response.GetTypedHeaders().ETag = etag;
Response.Headers.CacheControl = "private, no-cache";
return Ok(new ProductDto(product.Id, product.Name, product.Price));
```

## Preconditions on mutations

For PUT, PATCH, or DELETE, `If-Match` means “perform the mutation only if this is still the current version.” A robust endpoint has two layers:

```text
HTTP comparison before mutation
    missing required If-Match -> 428 Precondition Required
    supplied validator differs -> 412 Precondition Failed

database concurrency check during SaveChanges
    row changed after the preliminary read -> DbUpdateConcurrencyException -> 412
```

```csharp
var currentEtag = ToETag(product.RowVersion);

if (!IfMatchSatisfied(Request, currentEtag, out var missing))
{
    return missing
        ? StatusCode(StatusCodes.Status428PreconditionRequired)
        : StatusCode(StatusCodes.Status412PreconditionFailed);
}

product.Name = dto.Name;
product.Price = dto.Price;

try
{
    await db.SaveChangesAsync();
}
catch (DbUpdateConcurrencyException)
{
    return StatusCode(StatusCodes.Status412PreconditionFailed);
}

Response.GetTypedHeaders().ETag = ToETag(product.RowVersion);
return NoContent();
```

EF remembers the original value of a configured concurrency token. Its update is conceptually guarded by both identity and that original value:

```sql
UPDATE Products
SET Name = @name
WHERE Id = @id
  AND RowVersion = @originalRowVersion
```

Zero affected rows produces `DbUpdateConcurrencyException`. The preliminary HTTP comparison gives the client a precise response, while this database predicate closes the race between the initial read and `SaveChanges`.

`If-None-Match: *` expresses create-only behavior for a client-chosen URI: perform the operation only when no current representation exists. Use `409 Conflict` for a domain conflict rather than substituting it for the validator-specific `412` response.
